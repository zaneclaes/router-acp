# Local Markdown workflow

Use the repository's established roadmap and linked plans. Use an explicitly
supplied roadmap path first. If several sources are plausible, resolve the
source before scheduling. For a new repository, propose ROADMAP.md and plans/.
Preserve requirements and history. File edits do not grant execution authority.

The router owns work identities, attempts, review receipts, and wake delivery.
Repository skills own selection rules, checks, integration, and release policy.
Use planner_workflow to record assignments, evidence, review, and dispositions.
Use delegate_task with work_id for isolated implementation children. Review
every artifact. Send corrections to the same child. After a process exits,
resume the same work identity with a new attempt and its retained evidence.

Accept steering, bug reports, attachments, and status requests while work runs.
Route a correction to its original owner. Record specific blocked or watching
results without stopping independent authorized work. An empty queue is not
completion. Required evidence and all admitted input must be reconciled first.

Only the human or the repository's enforcement layer grants authority. A mode,
model message, roadmap edit, or monitor does not authorize merge, deployment,
publication, or cleanup. Run declared checks. A local change can complete with
local verification. Require release evidence only when repository policy does.
