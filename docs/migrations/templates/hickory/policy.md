# Hickory planner policy template

Use this content as the repository-relative Markdown profile selected by Hickory.
Keep Hickory policy here and keep router core neutral.

## Required behavior

1. Bind every implementation child to one authentic Linear ticket.
2. Preserve the existing EPIC parent and child presentation in `kory-code/relay/sessions.mjs`.
3. Keep ticket loading and ticket context in the existing configured ticket path.
4. Preserve the exact handoff labels consumed by the existing Hickory skills and relay.
5. Reuse the existing role skills through the YAML mappings.
6. Require the existing `/ship-pr` human gates for child finishing.
7. Keep merge and production deploy authority outside model prose.
8. Keep the parent as coordinator. The parent has no implementation PR.
9. Enforce one ticket, one durable child, and one PR for each Hickory implementation unit.
10. Keep corrections on the same ticket, child, and work identity.

The policy cannot create a ticket, merge a PR, or deploy to production by asserting permission in a prompt.
The existing Hickory enforcement layer remains authoritative.

The router worker handoff labels are `commit_paths_ready`, `waiting`, `lease_requested`, `ownership_requested`, `staging_gate_request`, `round_verified`, `round_failed`, and `reassignment_required`.
Keep these labels exact when the Hickory adapter forwards them.
Do not replace them with free-form phase names.

## Role ownership

`create-plan` binds or refines the Linear ticket and EPIC plan.
`select-plan` resolves eligible children, dependencies, ownership, and pool capacity.
`implement-work` performs the complete bounded ticket assignment.
`review-work` checks the child artifact and returns revision-bound acceptance or corrections.
`finish-work` invokes `/ship-pr` under its existing human approval contract.
`integrate-plan` verifies shipped outcomes and dependency satisfaction.

The `finish-work` mapping is intentionally `ship-pr`.
The wrapper passes the accepted revision, ticket, child, branch, and existing handoff receipts.

## Configuration and setup owners

Effective settings are generated by `kory-code/relay/agent-settings.mjs`.
Fleet defaults come from `kory-code/router.yaml`.
Workstation seed behavior comes from `hickory-infra/modules/dev_workstation/startup.sh`.
EPIC presentation and child lifecycle integration remain in `kory-code/relay/sessions.mjs`.

Remove retired `orchestration:` fields only with a compatible router pin.
Preserve valid user overrides.
Surface invalid mapped skills during configuration validation.
